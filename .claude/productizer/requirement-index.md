# Requirement index

GENERATED - do not edit by hand. `build-requirement-index.sh` writes the table
between the two markers from the Requirements and Acceptance criteria sections
of `spec.md`, and its `--check` (the `requirement-index-current` check) reports
any row that has drifted from them, a hand edit included. To change a row,
change the spec and regenerate.

One row per requirement, in id order. **Pattern** is the heading the
requirement is filed under. **Verified by** is each check its acceptance row
cites, `—` where it has no row, and `no check cited` where the row names none.
There is no Area column: the spec files no requirement under a `#### ` area
sub-heading, and a column of placeholders would read as data.

Why this is its own file: inside the spec, a lookup for one requirement also
read its index row and the rows around it, and the retrieval eval summed 32%
more text read. Why this file's structure is what it is: the builder rewrites
only what sits between exactly one begin and one end marker, begin first, and
refuses (exit 2) otherwise; it also refuses when the spec itself carries a
marker, because a table left there would be one nothing writes or checks.
